# Dewon Fried Chicken — website

Seven pages, no build step, no CDN, no third-party requests. Open
`index.html` through a local server and it runs.

```
python3 -m http.server 8000
```

A server is needed for local preview because Chrome blocks web fonts loaded
over `file://`. On real hosting this does not apply — upload the folder and
it works.

## Pages

| File | What it is |
|---|---|
| `index.html` | Home: hero, the seven-sauce seal, signature dishes, buffet and group teasers |
| `menu-a-la-carte.html` | The full list with prices, the category rail and the order tray |
| `menu-buffet.html` | Buffet price, today's dishes, the 24-day rotating menu, times |
| `parties.html` | Groups and parties, with a request form |
| `reservations.html` | Three request modes: buffet, à la carte, or a custom dish list |
| `find-us.html` | Address, map, hours, social channels, delivery links |
| `franchising.html` | The franchise proposition and an enquiry form |

## Editing it

**Business details** — `assets/js/config.js`. Phone, WhatsApp, address,
opening hours, social links, the seven sauces, group sizes. Nothing
business-specific is hardcoded in the pages. Any link left empty is removed
from the page rather than left pointing nowhere.

**The menu and prices** — `assets/js/menu-data.js`. One file drives the
à la carte page, the order tray and the reservation picker, so a price is
changed in exactly one place. Source of truth is
`08-menu/menu-reference.md` in the project.

**The buffet's daily dishes** — `assets/js/buffet-menu.js`. See the
next section.

**Photographs** — see `PHOTOS.md`. Drop files into `photos-raw/`, run
`node tools/photos.mjs`, and the cut-outs, the portrait crop and the
falling-herb layer are generated into `assets/images/`.

**Page structure** — the HTML files are plain and can be edited directly.
They are also generated by `node tools/build.mjs` from partials, which is
how the header, footer and order dialog stay identical across seven files.
If you would rather not use it, delete `tools/build.mjs` — nothing at
runtime depends on it.

> **Do not run `build.mjs` as it stands.** The HTML files have been
> edited directly since it was last in sync (the 13,70 € buffet price,
> the removed Tuesday tier, the rotating buffet menu). Running it would
> overwrite those pages with older versions.

## Updating the buffet menu

The buffet is served on weekdays and changes every day. Behind the
scenes it is 24 different buffet days (about a month of weekdays), then
back to day 1 — visitors only ever see dates, never the day numbers.
Every day is written out in one file, **`assets/js/buffet-menu.js`**,
and the buffet page works out which day is today by itself.

**To change what is served on a day:**

1. Open `assets/js/buffet-menu.js` in a plain text editor (Notepad,
   TextEdit, VS Code — not Word).
2. Find the day. Each one starts with a line like `═══ DAY 7 ═══`.
3. Change the dish names inside the quotes. Every dish is written
   `"Finnish name | English name"`; if both languages use the same name,
   write it once: `"Watalappan"`. Leave the quotes, commas and brackets
   as they are.
4. Save (keep the file as UTF-8 so ä and ö survive).
5. Upload that one file to the host, replacing the old one. **Nothing
   needs rebuilding**, and no other file changes. If the old menu still
   shows, reload once with Ctrl+F5.

To check a day before it comes round, open
`menu-buffet.html?day=17` (any number 1–24).

What each day holds — the kitchen's counts, listed again at the top of
the file:

| Key | Category | Per day |
|---|---|---|
| `kasvikset` | Salaattibaari (salad bar) | 8 |
| `salaatit` | Ruokaisat salaatit | 2 |
| `hedelmat` | Hedelmät | 4 |
| `kana` | Friteerattu kana | `pala` (`siivet` / `koivet` / `luuton`) + `kastike` |
| `srilankalainen` | Sri Lankalainen pääruoka | `riisi` + `liha` + `kasvis` |
| `suomalainen` | Suomalainen pääruoka | `paaruoka` + `lisuke` + `kasvis` |
| `keitto` | Keitto | 1 |
| `lisukkeet` | Rapeat lisukkeet | 3 |
| `leipa` | Leipä | 3 |
| `jalkiruoka` | Jälkiruoka | `suomalainen` + `srilankalainen` |

On the page these are shown as three panels: **Salad bar** (salad bar,
hearty salads, fruit), **Mains** (chicken, the two mains, soup, crispy
sides, bread) and **Desserts & drinks**.

The cold drinks, the hot drinks, and the fries and onion rings that
come with the chicken are the same every day. They are in `everyDay`
at the top of the file, not in the days.

**Which day is today.** `startDate` at the top of the file is day 1
and must be a Monday–Friday. From there each weekday is the next day
(Finnish time), Saturdays and Sundays are skipped, and after day 24 it
starts again from day 1. To restart the cycle, set `startDate` to the
weekday that should be day 1. At the weekend the page shows Monday's
buffet as "Next buffet", and the calendar always shows the next two
weeks of buffet days so guests can look ahead.

Why a JS file rather than a spreadsheet: the site has no build step and
no server code, and a CSV would need both (a fetch that fails from
`file://`, and a parser). This matches `config.js` and `menu-data.js`,
which are edited the same way.

## How ordering works

The menu comes first, the channel second. Add dishes and a tray appears
with the in-house total. "How to order" then offers the routes:

- **WhatsApp** — sends the itemised list as a message. The list survives.
- **Call** — the list stays on screen to read out.
- **Wolt** — Wolt cannot receive a cart from another site. That is a Wolt
  limitation, not a bug here. The dialog says so, offers a one-tap copy of
  the list, and shows what the same order costs on Wolt versus in-house.

Every item is €2 dearer on the platforms. The dialog states the difference
in euros for the actual order in the tray, because that gap is the whole
argument for ordering direct.

## Design

Light-first: white cards on a warm cream ground, orange doing the loud
work, black carrying the type. Layout language taken from cluckin.pk —
the horizontal product card with the photo right and a round `+`
overlapping it, the category pill rail on a colour band. Component
primitives follow shadcn/ui structure.

Colour is constrained by measured contrast, not taste:

| Combination | Ratio | Use |
|---|---|---|
| `#f5822e` on white | 2.59:1 | fills only, never text |
| black on `#f5822e` | 7.61:1 | so orange fills take **black** type |
| white on `#c24d0e` | 4.81:1 | the deep orange, where white type is needed |
| `#b4571a` on white | 4.86:1 | orange type on paper |

The orange is sampled from the logo file, not guessed.

Type is Archivo (variable, weight and width axes) and Instrument Sans,
both self-hosted from `assets/fonts/`. Self-hosting removes a third-party
request and sidesteps the EU position on the Google Fonts CDN.

## Libraries

Vendored into `assets/vendor/`, none loaded from a CDN:

- **Open Props** — radii, shadows and easings, so those come from a
  known-good scale rather than being invented per component.
- **Swiper** — the signature-card carousel. Active below 720px only; above
  that the slides fall back to a grid, because a carousel is right on a
  phone and wrong on a desktop.
- **Lucide** + **Simple Icons** — subset to the 33 icons actually used and
  inlined as a sprite in `assets/js/icons.js` (11 KB instead of 416 KB).

## Security

A static site has no server code, database or login to break into, so
the protection that matters is what the browser is told to allow. All of
it is in **`vercel.json`** and is sent as HTTP headers on every page:

- **Content-Security-Policy** — scripts only from this site (plus Google
  Analytics, if it is ever switched on), no inline scripts at all, no
  plugins, the page cannot be framed by another site, and forms can only
  post to this site, Formspree or Web3Forms. Inline `<script>` and
  `onclick=`-style attributes are forbidden, so none are used; keep it
  that way when editing (put code in `assets/js/`). Using a different
  form service means adding it to `connect-src` and `form-action`.
- **Strict-Transport-Security** — browsers only ever use HTTPS.
- **X-Frame-Options / frame-ancestors** — nobody can embed the site in a
  frame (clickjacking).
- **X-Content-Type-Options, Referrer-Policy, Permissions-Policy,
  Cross-Origin-Opener-Policy** — no content sniffing, no full URLs leaked
  to other sites, camera/mic/location/payment APIs switched off.

Forms carry spam protection without a captcha: a hidden honeypot field,
a 3-second minimum before sending, and length limits (`assets/js/app.js`,
`guardForm`). **`.vercelignore`** keeps the tools, docs and 17 MB of
unused source photos off the live site. `/.well-known/security.txt` says
where to report a security problem.

Checked by serving the site locally with exactly these headers and
browsing every page (menu, tray, order dialog, calendar, language
switch, map, forms): zero policy violations.

## Search (SEO)

- **Every page** has its own title and description written around the
  local search phrases (Kaleva, Sammonkatu, lounasbuffet Tampere,
  fried chicken Tampere, Epassi), a canonical URL, Open
  Graph and X card tags, and the share image `assets/images/og-cover.jpg`
  (1200×630, cut from the hero photo).
- **`index.html`** carries the Restaurant structured data: address,
  map coordinates (from OpenStreetMap, where Dewon is already mapped),
  phone, cuisines, price range, menu, reservations, payment methods,
  social profiles. No self-published star rating — Google ignores those.
- **`sitemap.xml`** lists the seven real pages at their real URLs;
  **`robots.txt`** points to it. `sauces.html` is a standalone widget
  and is `noindex`.
- **Search crawlers always get the Finnish page.** The site switches to
  English for non-Finnish browsers, and crawlers report English — so
  Google was indexing English text under Finnish titles.
- **Speed**: the hero photo was one 2.7 MB file for every device; it is
  now 83 KB on a phone, 171 KB on a laptop, 311 KB on a large screen.

**After it is live:**

1. **Google Search Console** (search.google.com/search-console): add the
   domain, verify with the DNS TXT record at the registrar, then submit
   `https://dewon.fi/sitemap.xml`.
2. **Google Business Profile**: claim or check it — for "lunch near me"
   searches it matters more than the website. Use the same name, address
   and phone as the site, word for word.
3. Test the structured data at search.google.com/test/rich-results and a
   share preview by pasting the URL into WhatsApp.

## Accessibility

Checked in a headless browser at 390×844 and 1440×900, not by eye:
contrast ratios against resolved backgrounds, touch-target sizes, keyboard
tab order with the dialog open.

Zero contrast failures across all seven pages at both widths. The order
dialog traps focus and returns it to the trigger on close. Reduced-motion
is honoured — every animation stops.
